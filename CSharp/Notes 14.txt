Expression Trees : Feature that allows representation of code as data
They are Tree like structures where each node represents operations, variables, constants and other code elements
Expressions are not Compile time Units. We need to compile during execution to delegates
They may return a value or just perform an action such as calling a method
Expressions trees that represent lambda expressions can be executed
Compiled expressions can be reused 

Common classes in System.Linq.Expression namespace
  - Expression - base class for all expressions
  - LambdaExpressions : Representation of lambda functions
  - BinaryExpressions : Represents binary operations
  - MethodCallExpressions : Represents method calls

Usages : are invaluable tool to dynamically create, manipulate or inspect code in a flexible and efficient way
         - are used in implementing dynamic filtering, sorting and pagination
         - used to build complex custom queries (Linq queries to SQL database)

Limitations : not used for all c# constructs (like loops, try catch blocks...)
              performance overhead
              complexity in managing and manipulating complex queries using expression trees

       TPL makes developers more productive by adding parallelism and concurrency to applications
       TPL handles work partitioning, scheduling of threads on the pool, state management, cancellation support and other low level details
