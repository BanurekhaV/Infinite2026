Filters : are framework attributes that allow some logical code on a particular action/result/exception
 - Allows in performing certain functionalities (Caching, Logging, Authentication, Authorization etc..) during, before or after action invoked, result executed or on getting an exception

Exceptions in MVC : are done in large scale
  - try catch and finally block
  - Overriding OnException()
  - Using [HandleError] attribute (built-in)
  - Setting up a global execution filter
  - Handle Application_Error() Event
  - Extending HandleError Attribute

Available Filters :
  1. Authentication Filter  ---> IAuthenticationFilter  (OnAuthentication(), OnAuthenticationChallenge())
  2. Authorization          ---> IAuthorizationFilter   (OnAuthorization())
  3. Action                 ---> IActionFilter   (OnActionExecuted(), OnActionExecuting())
  4. Result                 ---> IResultFilter  ( OnResultExecuted() , OnResultExecuting())
  5. Exception              ---> IExceptionFilter (OnException())

Available Attributes :
  1. ValidateInput
  2. Authorize
  3. HandleError   -- Exception Filter
  4. OutPutCache   -- example for ResultFilter

Apart from the above, we can create custom filters
- A filter can be applied at 3 different levels
   1. Global Level ( applicable to all controllers and action methods of the application)
   2. Controller Level ( applicable to all action methods of that controller)
   3. Action Method Level ( applicable to specific action methods)

Limitations to HandleError attribute class:
 1. We cannot log the error
 2. Not possible to handle exceptions raised outside the controllers (eg. invalid url)
 3. Scenario-based exception handling is not possible.  (Eg ajax request and non-ajax request)

To overcome the above limitations, we can work with Custom Filters
