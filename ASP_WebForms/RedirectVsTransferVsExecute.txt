Navigation : Moving from one resource to another (within the application or across application, in the same server or different server)

- Response.redirect : The object transfers to the given page permanently and ends the processing of the first page, and continues processing the new page
 - It also sends a command back to the browser (that it stopped processing the current page and has started processing the new page - leads to unnecessary round trip)

Usage : When we don't mind the users knowing the url address and resources
        Round trips are not a concern
        We don't want to preserve the state of the current page
        When we are not only redirecting to a new page but also a new server

Server.Transfer - Helps in navigating between pages of the same application, or pages within the applications of the same server
   - The current/first page is still in the memory of the server, and hence we can read the values (state management)
   - the page is not permanently redirected.

Usage : To transfer current page to another in the same server
        To preserve server resources and avoid round trips
        To preserve the state of the current page
        To not disclose the url address of all navigating pages to the end users

Server.Execute - same as Server.Transfer, except that the transfer() terminates the execution of the current page and starts executing the new page, whereas execute() processes the second page request without leaving the current page. Post completion, returns back to the previous page/firstpage
