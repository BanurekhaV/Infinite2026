Views : are relations that are not of the conceptual model, but is made visible to the user as virtual relation
        - the database will have only the view definition but no data
        - Every time we query a view, the definition constructs the actual query using the base/underlying or original tables

-- all dml operations are successful thru a view, when the view is made out of a single table
    - provided the other columns of the base table can take either a null or default values

-- multiple base table views
   -- dml operations may not succeed or may effect updations that were not intended, making the database less integrated

used defined constraints :
Check : enforcing certain type of values only 
Triggers : are reusable piece of code like any procedure or function
           they are used to enforce/define business rules or constraints
           they are not called explicitly, instead they get fired automatically on certain events
           they can be written as before/after or instead of the event
           they are dml or ddl based

Magic Tables : are temporary tables/storage that gets created within a trigger body during its execution
  - their scope is within the trigger body only
  - they are 2 in number
     1. Inserted table
     2. Deleted Table

updation is always delete followed by insert 

-- Instead of Triggers are triggers that execute the body of the trigger instead of the actual event
-- helps resolve issues with view updates/inserts
