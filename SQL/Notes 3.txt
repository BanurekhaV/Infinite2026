Exists : tests for existence of rows in the result of the subquery
   - If found the search does not continue in the inner query and flags a true
   - If not found inner query flags a false and continues the search

Exists is comparable to in, while not exists is to not in

Case : works as an alternate for conditional check

simple case : case keyword is immediately followed by case expression and before a when statement

searched case : case keyword is followed by when statement. There is no case expression between case and when statements

Nested case : case within case

Set Commands : are operators that can work with multiple result sets
Rules for using set commands :
  - The result set of 2 queries must have same number of columns
  - The datatypes of the columns should be same
  - The positional ordering of the columns must be same
  - Order by can used only on the final result

Union -- combines 2 result sets and removes duplicates if any
Union All -- includes duplicates
Intersect - includes only common values of 2 result sets
Except - includes unique values of the first result set as against the 2nd result set
 
CTE : Common Table Expression 
     - Are expressions that allow us to define the query output as a temporary storage, which is available only within the execution scope
     - We can perform DML operations
     - We can have multiple CTE's separated with a ','
     - One CTE can refer to another CTE
     - We can have recursive CTE's
     - On being referred or used once, the CTE will no longer be available

Advantages of CTE's
  - Reusability
  - More Readable
  - Does not occupy memory
  - Used for complex queries that can be broken into multiple CTE's

Recursive CTE's :
 with <expression name>(columnlist)
   as 
   (--Anchor Members/ initial query
      union all
    -- recursive member that references the <expressionname>
     recursive query
    -- includes a terminator
  )

All Queries : Any query will have to be parsed, compiled with a query plan for execution, and then executes the plan

Stored Procedures : Are SQL Statements that are parsed, compiled with an execution plan. Once Executed, the plan along with the query will be saved as an object in the database schema
 - This allows reusability
 - Provides better performance than normal queries
 - Can take input parameters
 - Can give away output parameters
 - Every procedure returns an integer value only
 - Can be used to implement DML operations
 - Can call other procedures from within
 - Can call other functions from within
